# WeChat Pay Channel Guide

## 概述

微信支付覆盖 App 支付、H5 支付、小程序支付、公众号支付和 Native 扫码支付。微信支付失败常见原因包括用户取消、订单超时关闭、签名错误、回调延迟、商户号配置异常、网络超时和微信侧风控。

微信支付排障时，要区分“用户未完成支付”“微信已支付但商户未收到回调”“商户请求微信失败”“商户处理回调失败”。

## 常见失败类型

| 内部失败码 | 渠道错误码示例 | 原因类型 | 说明 | 建议 |
| --- | --- | --- | --- | --- |
| `USER_CANCELLED` | `WX_USER_CANCEL` | `USER` | 用户在微信收银台取消支付 | 建议用户重新发起支付 |
| `CHANNEL_TIMEOUT` | `WX_TIMEOUT` | `NETWORK` | 调用微信支付接口超时 | 建议查询微信侧订单状态，必要时补单 |
| `ORDER_CLOSED` | `WX_ORDER_CLOSED` | `USER` | 用户超时未支付，微信订单关闭 | 建议重新创建支付单 |
| `SIGN_ERROR` | `WX_SIGN_ERROR` | `SYSTEM` | 签名或证书配置错误 | 建议检查商户密钥、证书序列号、签名算法 |
| `MCH_NOT_EXISTS` | `WX_MCH_NOT_EXISTS` | `SYSTEM` | 商户号不存在或配置错误 | 建议检查商户号和应用绑定关系 |
| `CALLBACK_VERIFY_FAILED` | `WX_CALLBACK_SIGN_FAIL` | `SYSTEM` | 回调验签失败 | 建议检查平台证书、回调验签逻辑和时间戳 |
| `RISK_REJECTED` | `WX_RISK_REJECT` | `RISK` | 微信风控拒绝交易 | 建议用户更换支付方式或稍后重试 |

## 支付日志解读

| 事件类型 | 含义 |
| --- | --- |
| `CREATE_PAY` | 系统创建支付流水 |
| `REQUEST_CHANNEL` | 系统请求微信支付接口 |
| `CHANNEL_RESPONSE` | 微信同步响应 |
| `CALLBACK` | 微信异步支付通知 |
| `QUERY` | 系统主动查询微信订单状态 |
| `ERROR` | 系统内部处理异常 |

## 典型场景

### 用户取消支付

证据通常包括：

- 支付流水 `status` 为 `CANCELLED` 或 `FAILED`。
- 内部失败码为 `USER_CANCELLED`。
- 渠道错误码为 `WX_USER_CANCEL`。
- 日志中出现 `CALLBACK/FAILED` 或收银台取消状态。

建议回答方向：

这是用户侧取消导致，不属于渠道或系统异常。建议用户重新发起支付，或更换其他支付方式。

### 微信接口超时

证据通常包括：

- `REQUEST_CHANNEL` 日志状态为 `TIMEOUT`。
- `latency_ms` 接近或超过系统超时时间。
- 渠道错误码为 `WX_TIMEOUT`。
- 未收到明确成功或失败回调。

建议回答方向：

这是渠道请求超时或网络链路异常。不能直接判定用户未扣款，应先调用微信订单查询接口确认最终状态。如果微信侧成功但本地失败，需要补单；如果微信侧未支付或关闭，可允许用户重试。

### 回调延迟或丢失

证据通常包括：

- 用户侧显示支付成功。
- 本地订单仍为 `PENDING`。
- 支付流水没有 `CALLBACK/SUCCESS` 日志。
- 后续 `QUERY` 能查到微信侧成功。

建议回答方向：

疑似回调延迟或回调处理失败。建议先主动查询渠道订单状态，再根据查询结果补单或修正本地订单状态。

## 处理建议优先级

1. 用户取消：允许重新支付。
2. 订单关闭：重新创建支付单。
3. 超时：先查渠道状态，再决定补单或重试。
4. 回调异常：优先查回调验签和回调处理日志。
5. 配置错误：检查商户号、证书、密钥和 AppId 绑定关系。
6. 风控拒绝：建议更换支付方式，不建议反复重试。

## 注意事项

- 微信支付存在同步响应和异步回调，不能只看同步响应判断最终支付结果。
- 超时场景要避免重复扣款。
- 回答用户时不要暴露商户密钥、证书序列号等敏感配置。
